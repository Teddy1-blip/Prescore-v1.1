# Prescore Studio v0.1

Внутренняя карта методологии и локальная лаборатория синтетических сценариев. Исходная ветка `prescore-product-v1`, база `cef0145f890a91fe8be58d5c740e7c7d250f4af8`. Версия атласа 0.1 от 10 ноября 2026 года.

## Запуск

Требуется Node.js 22.13 или новее. Проверено на 24.22.1. Выполните из корня репозитория или распакованного автономного preview:

```sh
node --experimental-strip-types scripts/prescore-studio.mjs
```

Откройте **http://127.0.0.1:4317/admin/studio**. Страница покажет номер запроса и команду `--approve`. Выполните эту команду во втором терминале из той же папки, затем нажмите «Проверить подтверждение». Номер действует пять минут. Владелец подтверждает доступ через файлы своей учётной записи ОС. База данных, ключи, npm-install, облачные сервисы и банковские документы для preview не нужны.

`STUDIO_PORT` и `STUDIO_DATA_DIR` можно переопределить. Одинаковые значения должны использоваться сервером и командой подтверждения. Сервер слушает только 127.0.0.1. Ctrl+C останавливает процесс. После перезапуска подтвердите браузер заново. Сохранённые версии переживают перезапуск.

## Первый эксперимент

1. Оставьте синтетическую компанию «Интеграция Б». При открытии сервер выполняет исходный расчёт. На карте 22 области. Щелчок по области раскрывает узлы, поиск находит русское название или код. Доступны масштаб, перемещение и мини-карта. Перетаскивание фиксирует положение карточки в браузере.
2. Нажмите **Создать черновик**. В редакторе текущей ликвидности замените выражение на `(CURRENT_ASSETS - RECEIVABLES) / SHORT_TERM_LIABILITIES`. Нажмите **Проверить**. Строки берутся из одного нормализованного баланса на отчётную дату.
3. Откройте **Рекомендации → Создать рекомендацию**. Заполните действие, подтверждение и условие повторной проверки. Выберите `RISK-FIN-CURRENT-LIQUIDITY`. Либо отредактируйте действующее определение `BUILD_RECEIVABLES_AGING`.
4. Нажмите **Рассчитать → Сравнение**. В этом случае коэффициент меняется с 2 до 0,8333. Финансовый компонент получает 328 из 400, сумма до потолка 928, потолок MEDIUM ограничивает Index уровнем 849. Осторожная долговая ёмкость сохраняется на уровне 100 000 ₽ в месяц. В разделе рекомендаций раскройте «Почему появилась». В трассе приведены входы, оценки, подавления и потолок.
5. В разделе **Версии** сохраните вариант. Обновите страницу и откройте версию из списка. **Экспорт JSON** готовит проверяемый пакет, **Импорт JSON** создаёт из него черновик. Экспорт требует актуального успешного расчёта. «Вернуться к baseline» восстанавливает исходную методологию и данные выбранной компании.

## Что доступно

| Область | Возможность |
|---|---|
| Весь атлас | 1 653 стабильных ID. Поиск, фильтрация, тематические связи, основания, замечания, подсветка и пути. Технические основания скрыты с обзорного полотна. В разделе «Версии» можно скачать полный JSON-реестр узлов и связей. |
| Источники | Две синтетические компании. Изменение пяти строк промежуточной БФО в рублях, явное пустое значение, включение финансовой отчётности и доступного БКИ. Исходный набор Integration B проверяет хеши fixture. |
| Формула | FSM-LIQ-001. Выражение с именованными строками, скобками, десятичными числами и операциями + − × ÷. Добавление или замена ссылки меняет реальные зависимости. Пустые значения и нулевой знаменатель видны в результате. |
| Правило | RISK-FIN-CURRENT-LIQUIDITY. LT/LTE, границы двух зон, тяжесть основной зоны, применимость по источнику, включение и отключение. Обязательный вход — FIN_CURRENT_RATIO. |
| Действия | Редактирование BUILD_RECEIVABLES_AGING и до 16 изменений определений суммарно. Новые действия используют finding финансового риска, штатную сборку, приоритизацию, разрешение конфликтов и планирование. Готовый горизонт определяет Action Plan. |
| Реальный пересчёт | Financial Analysis, Risk, Context, Index, Readiness, Credit Assessment, Capacity, продукты, рекомендации, 7/30/60, Explainability и модель отчёта. При недостатке наблюдений результат может оставаться неизвестным. |
| Остальная методология | Обзор кода и источников. Для новых исполняемых типов и дополнительных редакторов потребуется программная доработка. AI, оплаты, доступы и публикация с полотна не вызываются. |
| Версии | Копия, undo/redo правок, сохранение, открытие, сравнение данных или методологий, отдельный режим совместного изменения, проверка на двух компаниях, экспорт/импорт с проверкой совместимости. |

Два воспроизводимых пакета лежат в `studio/samples/`. **Ликвидность без дебиторской задолженности** сравнивает методологии на одном снимке. **Исключение БФО** сравнивает два набора источников на одной методологии. Второй пример даёт `INSUFFICIENT_DATA`, Index и ёмкость отсутствуют.
