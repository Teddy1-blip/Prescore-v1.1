# Partner commissions and settlement V1

Valid unique server attribution at checkout is immutable. Owner email + company INN match lead; real account must exist, blocked partner excluded. Conflicting brokers block checkout with ATTRIBUTION_NEEDS_REVIEW; missing/invalid/self curator creates no curator commission. BROKER policy1 =3000bps, CURATOR=1000bps of captured gross, not orders or forecasts. Gross650000: broker195000, curator65000; platform455000/390000 respectively. Unknown acquiring fee stays unknown.

Confirmation transaction creates commissions, ledger and durable PARTNER_PAYOUT outbox. No ADMIN approval. Worker bounded20, SQL SKIP LOCKED with 2-minute lease, provider idempotency keys, status polling, backoff30*2^attempt seconds capped3600, max5 then review. Partner must be existing/unblocked, VERIFIED tokenized recipient, no compliance hold, amount>0, configured provider + PAYOUT_API mode. Unverified=HELD; disabled/ACCRUAL_ONLY=PAYOUT_PENDING; no simulated real payment. Fake provider used only isolated tests. SPLIT_PAYMENT is not enabled; live payout contract/recipient onboarding is missing.

Only provider SUCCEEDED creates immutable payout ledger and PAID commission. Duplicate provider results add nothing. Processing amounts are reserved against beneficiary balance to avoid two workers spending the same positive balance. Negative net balance from refunds offsets later commissions; no automatic partner debit. Prior payout history is retained.

Refund policy1: each paid 30-day period retains duration proportional to gross minus cumulative refund; floor integer milliseconds. Later periods reflow, never before their confirmation; fully refunded periods cancel. Gross refunds and commission reversals append to ledger. Commission reversal uses floor(cumulative refunded * ratebps /10000) minus already reversed, eliminating rounding drift. Paid commissions create negative partner balance, unpaid commissions reduce payable. Refund request needs ADMIN reason/audit, provider confirmation and exact cumulative mapping. Unknown/lost provider response remains review and cannot be blindly retried. Failed refund does not revoke access.

Worker command: node --experimental-strip-types scripts/billing/payout-worker.mjs. Schedule externally after future deployment; never run against external DB as part of CI. Profile changes require future provider onboarding; ADMIN hold/release never changes verification to VERIFIED or payout to SUCCEEDED.
