# Настоящее приложение в GitHub Codespaces

Приватный порт 4189 обслуживает штатный `npm run dev` на Node.js 22. Порт 4188 в этой рабочей среде использовался отдельным QA-сервером.

## Запуск после остановки Codespace

В корне репозитория выполните `bash scripts/codespaces/dev.sh 4189`. Для первого запуска нужны Docker, Node.js 22 через NVM и установленные зависимости проекта. Откройте порт 4189 на вкладке Ports и перейдите на `/dashboard` под GitHub-аккаунтом владельца. При первом открытии GitHub может попросить подтвердить переход на порт.

PostgreSQL 16 использует отдельный Docker volume, собственные реквизиты и loopback-порт 55432. Оригиналы документов и секрет авторизации находятся в приватном каталоге пользователя `~/.local/share/prescore-codespace-dev`. Подтверждения регистрации и восстановления пароля для этой базы принимает локальная почта разработки с STARTTLS. Владелец Codespace может открыть приватный порт 18025 для проверки письма.

`CHECKO_API_KEY` читается из окружения Codespaces. Если ключ не предоставлен, авторизованный запрос к `/api/checko` сообщает `NOT_CONFIGURED`. Добавление компании и обработка документов доступны независимо от Checko.

Тестовая учётная запись с загруженным комплектом доступна владельцу этого Codespace в приватном файле `~/.local/share/prescore-codespace-dev/browser-test-account.json`. Откройте его внутри Codespace для входа. После пересоздания среды можно зарегистрироваться заново и подтвердить почту через локальный почтовый ящик разработки.

## Проверка 15 ноября 2026 года

Chromium прошёл штатную регистрацию с подтверждением письма и вход. Через приватный HTTPS-туннель дополнительно проверены повторный вход, выбор ранее сохранённой компании, загрузка TXT, открытие сохранённого анализа после обновления, импорт годовой БФО и ОСВ 62, реестр покупателей и комплект документов. Файл, скачанный отдельно и внутри выбранного ZIP, совпал с отправленным содержимым. Второй синтетический клиент зарегистрировался и подтвердил почту через приватный туннель. Запросы этого клиента к досье и оригиналу документа первого пользователя вернули 404.

| Запрос | Фактический результат |
| --- | --- |
| GET /api/health | 200 |
| GET /api/ready | 200 READY, схема 0012, хранилище READ_WRITE |
| GET /dashboard без сессии Prescore | 307 на /login |
| GET /api/dossier, GET /api/workspace | 401 без входа, 200 после входа |
| POST /api/analysis | 200, возвращён ID сохранённого анализа |
| POST /api/dossier, БФО и ОСВ | 201 при первом импорте, 200 при повторном, по одному источнику каждого типа |
| POST /api/documents, GET /api/documents?download | 201 и 200, байты проверены |
| GET /api/checko с доступом к анализу | 503, providerStatus NOT_CONFIGURED, providerConfigured false |

Синтетический пример из `inputs.zip` содержит поступление 100 000 ₽, конечный банковский остаток 150 000 ₽ и дебетовое сальдо по 62.01 в размере 1 800 ₽. Для повтора загрузите TXT через «Новый анализ», годовой CSV в «БФО», CSV по счёту 62 в «Контрагенты». Технические реквизиты, клиентские файлы и почта разработки в репозиторий не включаются.
