## Architecture and contracts

`ClientReportInputV1 → buildClientReportModel → ClientReportModelV1 → React / PrintReport`.

The input requires Explainability, Action Plan, Recommendations, Product Selection, Debt Capacity, Credit Assessment, Financing Readiness, Prescore Index and explicit `asOfDate`. Company display metadata and portfolio are optional. Neither raw transactions nor provider payloads enter components. React receives one typed model.

Versions:

- `PRESCORE-CLIENT-REPORT-1.0.0-SHADOW`
- `PRESCORE-CLIENT-REPORT-POLICY-1.0.0`
- `PRESCORE_CLIENT_PRESENTATION_V1`
- Render mode: `INTERNAL_PREVIEW`.
- Policy fingerprint: `client-report-policy:6eadb01baf09441e06eb6ca573980894`.

The model contains meta, company, hero, index, readiness, capacity, primaryFactors, contextHighlights, productFit, recommendations, actionPlan, dataQuality, detailedSections, sources, limitations, printMeta and technical metadata. Reusable typed metric, status, factor, product, action and section contracts separate presentation from analytics.

The deeply frozen policy defines section order, print order, executive limits (5 factors / 3 products / 5 actions), 8 initially visible recommendations, disclosure defaults, confidence / severity / fit / status labels, CTA precedence and target responsive widths. Its complete configuration contributes to the deterministic fingerprint. Copy and source-kind vocabulary are centralized. Canonical action and recommendation wording remains exact.

## Client journey and information architecture

Client journey: current profile → material factors → financing mechanics → first actions → supporting documents → conditions for another analysis.

Six primary destinations:

1. Обзор
2. Почему такая оценка
3. Возможности финансирования
4. Что делать
5. Данные и ограничения
6. Полный анализ

The first-screen design prioritizes an executive interpretation, Index, separate Readiness, monthly Capacity and the current action link. Material drivers, data limitation and actual rerun conditions follow within the overview. This is the intended 30-second hierarchy; usability and exact fold position **remain unverified visually**.

One primary CTA is selected deterministically: data blocker → «Добавить данные»; otherwise canonical DAY_7 focus → «Открыть план действий»; otherwise → «Посмотреть полный отчет». There is no synthetic timed rerun button. Upload and real reanalysis remain in the existing workspace.

Navigation groups Analysis, Financing, Data and Help exist only in the preview shell. All previous workspace features remain reachable through the unchanged `/dashboard`. Links to offers/applications and the existing analyst explicitly lead to the existing cabinet; no unsupported deep-link state is invented. This is not a production navigation cutover.

## Metrics and financing

Index displays the canonical value /1000 and four named components with native progress bars and text values. Component bars express geometry only. Unknown / global-stop results do not create zero-filled component charts.

Readiness has its own level, interpretation, confidence and constraints. It is not derived from the displayed Index inside this adapter. Confidence labels are «Высокая подтвержденность», «Достаточная подтвержденность», «Требуется подтверждение», «Недостаточно данных».

Capacity prominently displays the canonical prudential monthly incremental service amount, its calculation status and confidence. Nearby text explicitly states that it is not a bank decision or approved limit. Zero is retained as zero with the upstream restrained wording and a link to what to check first. Null remains unavailable. Partial does not suppress supported values.

Expanded Capacity details copy operating bases, existing service anchors, full months, 20%/25% boundaries and explicitly supplied scenario principal equivalents. No scenario is synthesized and no annualization or principal calculation is performed here.

Primary products follow canonical `primaryCandidateProducts` order, limited to three. Other families are disclosed separately; ranking is never recalculated. Cards copy purpose fit, capacity alignment, requested-product alignment and missing requirements. The interface separates financing **mechanics** from bank offers/applications. No bank choice, approval probability or bank policy is introduced.

Source references remain linked to Explainability claims and are not interpreted as independent new confirmation.

Only emitted recommendations are displayed. Initial recommendations retain canonical primary selection; the rest remain available in a lazy disclosure. Groups use data, debt/BKI, cash flow, financial statements, legal, financing case and product preparation language.

The 7/30/60 board preserves canonical horizons, sequence, focus, prerequisites, evidence, steps and recheck wording. Status is read-only. No completion checkbox, countdown, fake persisted state or promise that a completed task resolves a risk exists. Monitoring is shown separately. Horizon dates are explicitly analytical checkpoints, not legal deadlines.

Rerun text comes exclusively from canonical Action Plan rerun claims. Empty triggers do not become a fabricated 30-day reminder.

## Source transparency and limitations

Sources are grouped for readability by source kind, dates/period and confidence. Every factor points to an existing displayed group. Duplicate source groups do not produce dozens of identical rows. No raw provider payload, bank account or transaction text is exposed by this model.

«Важно учитывать» retains limitations with progressive disclosure. Methodology explains what Index, Readiness, Capacity and Product Fit mean. Technical versions/fingerprint are behind a technical disclosure and excluded from print. No internal risk codes appear in default client copy.

## FREE / FULL and preview seam

`buildClientReportModel(input, { entitlement: 'FREE' | 'FULL' })` requires an explicit entitlement. FREE returns company/date metadata and generic factual locked copy; it contains no Index, capacity, drivers, source evidence, products, action plan or paid claim IDs. FULL contains the supported report. This is a presentation projection, **not a replacement for server entitlement enforcement**.

`buildClientReportShadow` is an optional, failure-isolated seam. Errors return `CLIENT_REPORT_SHADOW_UNAVAILABLE`; no authoritative fields are changed.

The server-only route `/dashboard/report-v2` returns not-found unless `PRESCORE_INTERNAL_REPORT_PREVIEW=1`. It reads only checked-in synthetic preview models, never client analyses. Query `sample` selects healthy, partial, insufficient, zero, stop, defect or free; `print=1` selects an all-expanded PrintReport. Synthetic samples are explicitly labelled. The fixture-generation script creates demo material, not Golden expected results.

Future production cutover requires separate authorization, actual server FULL entitlement enforcement and connection to validated canonical outputs. The existing dashboard, APIs, uploads, CRM, BKI parser, admin controls and AI behavior are untouched. Block 19 may consume the model later; it is not implemented.

Scoped CSS tokens cover surfaces, text, borders, brand, restrained semantic colors, spacing, radius, shadow and maximum content width. Analytical prose has bounded line length. Cards are reserved for decision summaries; details and sources use lists, definition lists and tables. No chart library, animation library, decorative gauges or count-up animations were added.

Breakpoints: 1024, 768, 390 and 360 px; the desktop maximum is 1440 px review target. Grids use `minmax(0,1fr)`, mobile stacks sections, and tables use local overflow. No page-level fixed-width card pattern is allowed by static checks. Visible focus, native links/buttons, skip link, main landmark, labelled navigation, proper table headings, native disclosures and reduced-motion styles are present. Semantic colors are accompanied by labels. These are static fundamentals, not a claimed WCAG certification.

Loading states distinguish workspace, calculation and upload without invented percentages. Empty and unavailable states explain the missing result and an available next step; unavailable does not falsely promise that unsaved data is safe. Route loading/error components use these states. No raw exception is the primary copy.

## Print / PDF-ready

PrintReport consumes the exact same model. The print variant expands essential content, omits navigation/buttons/technical identifiers, provides company, INN, analysis date and status, and includes the prescribed disclaimer. ## Determinism, validation and safety

The adapter has no clock, random, network, storage, browser or LLM dependency. It does not invoke any analytical engine. Inputs are neither mutated nor recalculated. Unordered claim/source/candidate collections are ordered deterministically; canonical ranking and plan sequence are retained.

Validation checks compatible company/asOf, exact canonical numeric bindings and formatted values, executive/action copy, Readiness/confidence labels, existing claims/sources/actions/products, unique IDs, no omitted actions, no duplicate recommendation identity, plan horizons, ranking, one valid CTA destination, executive limits, FREE privacy and forbidden client wording. Main metrics are not recomputed in JSX. Presentation-only text vocabulary does not alter numerical or risk semantics.
