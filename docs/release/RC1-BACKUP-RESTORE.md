# Coordinated privileged backup and restore

Use PostgreSQL15 tools included in the shared image. `backup:create /absolute/new/set` invokes pg_dump custom format (schema+data+history+ledger+auth+audit+documents). Credentials are passed only via child environment, never command line/logs. `storage:backup` creates the same coordinated set rather than a misleading independently consistent storage snapshot. Manifest/checksums/source version/file count/bytes accompany a bounded gzip JSON-lines archive of UUID files and their metadata. No symlinks, config files, arbitrary filenames or tar extraction. Backup is sensitive privileged material; keep outside repository/public directories, encrypt at the destination, restrict access/retention. CI exports reports only, never the DB/storage archive.

Consistency guarantee: stop all app instances and workers, wait for in-flight requests/worker batches to finish, then set PRESCORE_BACKUP_QUIESCED=true and run backup. CLI obtains an additional backup advisory lock against competing backup CLI instances. This is not a live point-in-time snapshot of writes while serving traffic. Database dump uses PostgreSQL's consistent snapshot; storage is copied under the stopped-write window. Do not restart writers until verification finishes. Destination must be new; no overwrite. Final manifest is written only after complete DB/storage output. Interrupted backup remains incomplete and cannot be verified/restored; start a new backup set, do not purge data.

`backup:verify <set>` validates SHA256, storage entry checksums/count/bytes and pg_restore --list. `storage:backup:verify` verifies the coordinated set too. Restore requires PRESCORE_RESTORE_CONFIRM=EMPTY_DATABASE_AND_STORAGE, an empty PostgreSQL public schema and empty normalized storage directory. It uses pg_restore --single-transaction --exit-on-error, restores bounded validated files, verifies migration checksums/catalog and storage links. It never --clean/drop/truncate/overwrites a populated target. If interrupted after DB commit, keep that partial target offline and repeat into another empty target; no cross-resource atomicity is claimed. Never delete ledger or payment history to recover.

CI drill: real E2E source -> stop app/worker -> coordinated backup -> verification -> fresh independent DB/storage -> restore -> new app/worker -> post-restore auth/equality/download/application/billing/ledger assertions. Corrupt archives and non-empty targets reject. Missing/orphan/size/path/symlink checks use read-only storage:verify; it does not delete anything.

Actual interruption drill: with writers stopped, the isolated CI fixture ledger is transactionally locked while pg_dump starts. The backup process group is killed with SIGKILL before completion; the absent manifest and nonzero verify result prove rejection. The lock rolls back without row changes; a new coordinated set is created, verified and restored. Incomplete sets are retained, never cleaned automatically.
