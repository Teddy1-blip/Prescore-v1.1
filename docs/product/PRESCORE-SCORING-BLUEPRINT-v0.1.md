# Prescore · Scoring Blueprint v0.1

Внутренний черновик для ручной ревизии кредитной методологии. Срез на 9 ноября 2026 года. Столбец **Owner Review Comment** и последний раздел предназначены для решений владельца. Приоритеты A–D, клиентские формулировки и варианты будущей калибровки — предложения для обсуждения.

**Что получает компания.** Prescore описывает кредитную позицию, которую можно подтвердить документами на дату анализа. Балл снижают подтверждённые кредитные риски. Достоверность расчёта видна отдельно. При полном покрытии и отсутствии таких рисков возможны 1000 баллов. Буквально 1000 может появиться и у частичного результата, поэтому статус рядом с числом обязателен. Нулевое значение не имеет вероятностной интерпретации. Вероятность дефолта или одобрения, решение банка, лимит, долговая ёмкость и соответствие продукту в эту шкалу не входят.

## Действующий Prescore Index

`PRESCORE-INDEX-1.0.0-SHADOW` · `PRESCORE-INDEX-POLICY-1.0.0-PRE-CALIBRATION` · `PRESCORE_INDEX_RISK_CONTEXT_V1`. Политика фиксирована, результат сохраняет версию и отпечаток политики. При одинаковых допустимых входах и дате результат воспроизводим.

| Компонент | Максимум | Какие findings получают вклад |
|---|---:|---|
| FINANCIAL_STRENGTH | 400 | FINANCIAL |
| OPERATING_BEHAVIOR | 300 | CASH_FLOW, с одним точным исключением ниже |
| DEBT_CREDIT | 200 | DEBT_SERVICE, CREDIT_HISTORY, CREDIT_PORTFOLIO. Точный код RISK-CF-DEBT-SERVICE-BURDEN направляется сюда даже с исходным доменом CASH_FLOW |
| LEGAL_CORPORATE | 100 | LEGAL |
| **Итого** | **1000** | Только предъявленные CREDIT_RISK с зарегистрированным маршрутом |

| Severity | Доля максимума компонента | Вычет из 400 / 300 / 200 / 100 до контекста | Верхняя граница общего Index |
|---|---:|---|---:|
| CRITICAL | 0,60 | 240 / 180 / 120 / 60 | 549 |
| HIGH | 0,35 | 140 / 105 / 70 / 35 | 699 |
| MEDIUM | 0,18 | 72 / 54 / 36 / 18 | 849 |
| LOW | 0,08 | 32 / 24 / 16 / 8 | 949 |
| INFO | 0,00 | 0 / 0 / 0 / 0 | 1000 |
| Ни одного вычета | — | 0 | 1000 |

1. Для каждого учитываемого finding базовый вычет равен максимуму его компонента × коэффициенту severity. Объяснение хранит исходный finding, субъект, доказательства и версию.
2. Квалифицированная связь `CORROBORATES` добавляет 10% **к его вычету**, `MITIGATES` снимает 10%. Суммарная поправка ограничена диапазоном от −15% до +15%. Нужны связанный finding, совместимые ИНН, версия и дата, известные факты, доказательства и уверенность не ниже MEDIUM. Данные, заявленные клиентом, не дают численной поправки. `NEUTRAL`, `EXPLAINS` и `REQUIRES_REVIEW` имеют нулевой численный эффект.
3. Вычеты округляются до сотых. Их сумма в каждом компоненте ограничена его максимумом. Баллы компонента равны максимуму за вычетом ограниченной суммы. Сохраняются индивидуальные вклады, даже если их сумма превысила максимум.
4. Складываются баллы компонентов. К этой сумме применяется потолок по самому серьёзному учитываемому риску. Итог округляется один раз до целого. Потолок не вычитается из суммы второй раз. При `GLOBAL_STOP` обычные вклады не рассчитываются. Для итогов без числа баллы компонентов имеют лишь диагностический смысл. ### Покрытие, доказательность и доступность числа

| Component | Required Facts | Minimum Coverage | Full Coverage | Optional Enrichment | Missing Behavior |
|---|---|---:|---|---|---|
| FINANCIAL_STRENGTH | FIN_EQUITY, FIN_CURRENT_RATIO, FIN_ANNUAL_REVENUE, FIN_ANNUAL_NET_PROFIT | 2 из 4 | 4 из 4 | Чистые активы, оборотный капитал, сопоставимые периоды, покрытие процентов | 0–1 → общего числа нет. 2–3 → возможно PARTIAL |
| OPERATING_BEHAVIOR | BANK_OPERATING_TREND, BANK_TOP1, BANK_COVERAGE_ADEQUATE | 1 из 3 | 3 из 3 и BANK_COVERAGE_ADEQUATE = true | Волатильность, каналы расчётов, собственник, остатки | 0 → числа нет. Известное false может участвовать в минимальном счёте, но оставляет покрытие ограниченным |
| DEBT_CREDIT | BANK_DEBT_SERVICE_RATIO | 1 из 1 | 1 из 1 | БКИ компании, портфель и известный график | Без банковской доли общего числа нет. Отсутствие БКИ само не вычитает баллы |
| LEGAL_CORPORATE | LEGAL_LIFECYCLE | 1 из 1 | 1 из 1 | Взыскания, адрес, споры, сведения реестров | Без известного жизненного статуса числа нет. Для подтверждения глобального стопа нужны более строгие доказательства |

Факт засчитывается один раз, со статусом KNOWN, явно известным значением (0 и false допустимы), уверенностью факта и всех его доказательств не ниже MEDIUM, непустой доказательной базой и без предупреждений о конфликте, устаревшем или неготовом источнике. Для банковского компонента требуются обе границы периода. RiskFact первичен. Только если такого кода нет, допускается незаявленный клиентом ContextFact. Неопределённый RiskFact не замещается удобным значением из Context. [Проверка покрытия](../../lib/credit-engine/index/coverage.ts)

| Условие в порядке проверки | Статус / значение | Сопоставимость |
|---|---|---|
| Подтверждён хотя бы один GLOBAL_STOP | NOT_RATABLE_GLOBAL_STOP / null | Нет |
| Хотя бы один компонент ниже минимума | INSUFFICIENT_DATA / null | Нет |
| Минимумы выполнены, но покрытие ограничено, есть DATA_REVIEW, адресное REQUIRES_REVIEW либо неопределённость применения стопа | PARTIAL / число | Нет |
| Полное покрытие и ни одного из перечисленных ограничений | CALCULATED / число | Да |

Confidence — минимальная релевантная уверенность сводки Risk, компонентов и использованных доказательств. Для PARTIAL максимум MEDIUM, фактическая уверенность может быть ниже. БКИ и портфель не обязательны в *минимуме* Index. При этом текущий адаптер целенаправленно проверяет наличие BANK_STATEMENT, BFO, QUARTERLY и BKI. Если, например, БКИ не предоставлено, появляется `SOURCE_MISSING_COUNT` и возможно PARTIAL даже при всех четырёх ADEQUATE. Материальное различие между обязательностью **для числа** и для **сопоставимого результата**. При отсутствии исходных банковских метрик/выписки вызов сохранённого анализа вообще не доходит до Index. ## Реестр факторов

В реестре ниже **107 строк**, включая **все 41 уникальное правило Risk**, показатели без собственного штрафа, связи контекста, ограничения программ и будущие кандидаты. Некоторые из них меняют тип в зависимости от значения. Для этих ветвей в реестре даны отдельные строки с одним основным типом. Обозначение в квадратных скобках после кода различает строки документа и не меняет идентификатор правила. В строках без правила Risk приведены имя метрики, код Context, требование к продукту или явно помеченная будущая идея. Если у показателя нет собственного кода правила, первое поле служит указателем этой таблицы. Такие обозначения, как BALLOON и MASS-ADDRESS, не входят в программный реестр.

| Основной тип | Роль в расчёте |
|---|---|
| CREDIT_RISK | Подтверждённое правило может снизить свой компонент и ограничить общий Index |
| GLOBAL_STOP | Стоп для общей оценки Prescore, Index = null |
| DATA_REVIEW | Вопрос к данным. Прямой вычет 0. Существенная проблема может ограничить или исключить числовой результат |
| CONTEXT | Связь с подтверждённым риском либо нейтральное описание случая. Численная поправка возможна лишь на условиях политики выше |

В столбце **Current / Proposed** указаны статус и предварительный приоритет для разработки методологии (A — обязательно, B — важно, C — обогащение анализа, D — будущий кандидат). Приоритет не участвует в расчёте. «Метрика» означает реализованный расчёт без собственного правила Risk. «Кандидат» означает отсутствие отдельного правила на срезе. Указанный для него тип — возможная роль в обсуждении. В столбце **Proposed Threshold** прочерк означает, что численную границу для обсуждения не назначали. Все клиентские фразы и действия в реестре — редакционные примеры. Реальный клиентский результат выбирает рекомендации из действующего реестра по доказательствам и версии анализа.

Общие требования к доказательствам — ИНН и роль субъекта, идентификатор источника и факта, дата/период, сумма или значение с единицей, происхождение, достаточная уверенность. Границы применимости в адаптерах Risk: банк и текущее БКИ 90 дней, юридический источник 30 дней, годовой отчёт 550 дней, промежуточный 270 дней. Исторические сведения сохраняют свой исходный период. «Уточнить» в неизвестном состоянии означает отсутствие вычета и отсутствие вывода, что проверка пройдена. ### Операционное поведение · 300

Данные относятся к представленным счетам. Для тренда нужны не менее четырёх полных месяцев, сравниваются средние первой и второй половин. Для тренда и долговой доли допускается подтверждённое внутреннее окно полных месяцев при частичных граничных месяцах, без пропусков, перекрытий или неопределённого периода счёта. ## Глобальные стопы и действия клиента

Подтверждённый стоп даёт `NOT_RATABLE_GLOBAL_STOP` и `value = null`. Код сохраняет IDs доказательств, причину и дату, возвращает пустой список обычных начислений. Применяется к общей оценке Prescore. Обозначение CRITICAL в строке стопа не приводит к обычному потолку 549.

Прямой источник ФНС для жизненного статуса подтверждается в том числе совпадением хэша официально полученного PDF. Этот документ не подтверждает отсутствие судов, взысканий или проблем с адресом. При противоречии двух известных состояний на одну дату адаптер может вернуть неопределённый жизненный статус с обоими доказательствами. Для РНП историческая запись с доказанным исключением очищает лишь собственную запись. Голый положительный флаг Checko и неизвестное окончание не подтверждают действующую запись. Подтверждённая активная запись РНП сохраняется как INFORMATION/product-policy signal: она видна в анализе и рекомендациях, но не является GLOBAL_STOP, не уменьшает общий Index и не делает компанию NOT_RATABLE. Если факта РНП вообще нет, его опциональное правило пропускается; отсутствие этого источника само по себе не создаёт неопределённость по lifecycle-стопам. **Текущие 90+ по БКИ.** При положительной просроченной сумме и явно текущей длительности ≥90 дней по открытому обязательству с известным остатком движок выставляет `PRESCORE_CURRENT_90_PLUS_CONSTRAINT` внутри `RISK-BKI-CURRENT-OVERDUE`, тип CREDIT_RISK, тяжесть CRITICAL. |---|---|---|
| B | Слабый положительный капитал, снижение прибыльности, быстрая ликвидность, долговое плечо, Top‑3/5, волатильность | Подтвердить, какую новую информацию добавит каждая метрика поверх уже действующего риска. Значения метрик могут быть доступны сейчас |
| C | Транзитность, необычные операции, массовость адреса или руководства, изменения состава собственников | Критерий проверяемости, независимый источник, допустимое клиентское объяснение и защита от ошибочного вывода |
| D | Крупный разовый платёж как риск, нарушение ковенанта, кросс-дефолт, проблемная реструктуризация, зависимость от будущего рефинансирования | Договор, изменения, график, роли сторон, окно платежа и доказательство последствия. Событие в календаре не доказывает нарушение |
| D | Риск контрагента для самой компании, отраслевые нормативы, ОСВ и детализация 1С | Отдельно доказать связь с денежным потоком заёмщика, корректность периода и добавочную информацию. Сведения контрагента не переносятся на заёмщика по умолчанию |

### Предварительный порядок экспертной проверки

**A.** Начать с отрицательного капитала, повторных убытков, существенного падения выручки, текущей просрочки, тяжёлой долговой нагрузки и трёх lifecycle-оснований для остановки оценки. На одном досье видны размер вычета, потолок, доказательство и ближайшее действие.

**B.** Затем проверить концентрацию, показатели ликвидности, волатильность, рентабельность и соразмерность взыскания. Сопоставить двух похожих заёмщиков, у которых различается ровно одно доказательство.

**C/D.** Для обогащения и будущих факторов сначала сформулировать, какое управленческое действие меняется. Там, где нельзя назвать независимую причину ухудшения или источник, оставить наблюдение в пояснении.

# OWNER DECISIONS REQUIRED

| № | Решение владельца / кредитного эксперта | Что меняется в трактовке | Решение / комментарий |
|---:|---|---|---|
| 1 | Считать ли отрицательный капитал и его proxy одним основанием? Какую дополнительную информацию должны давать reported чистые активы и какая мера справедлива для двух показателей из одних строк оборотного капитала? | До решения за капитал и proxy были возможны два самостоятельных вклада. | **РЕШЕНО.** Отрицательный капитал — primary finding. Отрицательный net-assets proxy, если он дублирует ту же экономическую причину, остаётся в audit trail как TRIGGERED, но подавляется через suppressedBy и не создаёт второй штраф. Самостоятельный proxy сохраняется только когда adverse equity finding отсутствует. |
| 2 | Когда спад годовой выручки и спад банковских поступлений доказывают разные проблемы? Следует ли отдельно оценивать снижение ещё положительной маржи или прибыли? | Повтор одного и того же спада в БФО и выписке больше не должен давать два независимых штрафа за один период и третий штраф через corroboration. | **РЕШЕНО.** Если банковский период начинается не позже окончания годового периода БФО, падение поступлений считается тем же экономическим ухудшением: банковское правило остаётся TRIGGERED в audit trail, но подавляется через suppressedBy и не даёт второй вклад. Только полностью последующий банковский период (начало строго позже конца годового периода) может дать самостоятельный Operating Behavior risk как подтверждение устойчивости/продолжения спада. Если такой последующий риск уже получил собственный вклад, CORROBORATES не добавляет ещё +10% к финансовому штрафу. Положительное последующее восстановление по банку может по-прежнему MITIGATE исторический риск при достаточных доказательствах. |
| 3 | Сколько самостоятельных последствий признавать, если один платёж вызывает нехватку денег и взыскание? Какие из границ долговой доли 25/40%, низких дней 10/20% и взысканий 1/5% адекватны при разных моделях бизнеса? | Определяет допустимый совокупный эффект долгового и юридического событий, а также пользу отдельного фактора долгового плеча | |
| 4 | Достаточно ли Top‑1 для разных каналов продаж? Когда оставшаяся концентрация, волатильность или сезонность дают дополнительное подтверждённое основание? | Определяет, сохранять ли Top‑3/5 и волатильность только в пояснениях и какие пороги концентрации проверять на экспертных парах | |
| 5 | Как учитывать положительную просрочку, если известны только исторические дни? Какое значение придавать явно текущим 90+ в подготовке к финансированию и когда считать текущую и прошлую просрочку одним эпизодом? | Сегодня исторические дни могут влиять на тяжесть, но не подтверждают текущие 90+. Решение определяет требуемое доказательство и совместный эффект эпизодов | |
| 6 | При каких документированных условиях разовый платёж, реструктуризация, ковенант или кросс-дефолт становятся кредитным риском заёмщика, а когда остаются договорным ограничением? | От этого зависит предмет будущей проверки договоров и графиков. В текущем Index такие штрафы отсутствуют | |
| 7 | Должна ли подтверждённая запись РНП по любому поддержанному закону останавливать всю общую оценку либо только подготовку отдельных продуктов? Какие подтверждённые юридические события заслуживают самостоятельного вычета помимо текущих? | Активная прямая запись РНП больше не останавливает общий Index; lifecycle-стопы сохранены отдельно. | **РЕШЕНО.** РНП — INFORMATION/product-policy signal: 0 прямого вычета, не GLOBAL_STOP, но запись и evidence сохраняются для рекомендаций и будущих правил конкретного продукта/кредитора. |
| 8 | Какой комплект доказательств считать достаточным для сопоставимого результата? Должна ли компания с полным ядром, но без БКИ или квартальной БФО, оставаться PARTIAL? | Сегодня можно получить число без этих источников, но finding о недостающем семействе лишает результат сопоставимости. Это влияет на интерпретацию двух одинаковых баллов | |
