# Packaged build provenance v1

The existing `npm run build` captures actual source inputs **before** typecheck/Next compilation. `package-runtime.mjs` recomputes the same fingerprint after compilation, refuses changed inputs, and places the manifest at `lib/release/build-provenance.json` inside standalone. Artifact validation checks the fingerprint again and checks `.next/BUILD_ID`. Health reads that fixed packaged file once; `PRESCORE_SOURCE_SHA` and `PRESCORE_BUILD_TIMESTAMP` cannot override it. Missing/invalid metadata remains UNAVAILABLE/UNKNOWN.

`PRESCORE-SOURCE-INPUTS-1` recursively covers every regular file in `app`, `lib`, `public`, `scripts`, `db`, `types`, `tests`, plus the existing root files `package.json`, `package-lock.json`, `Dockerfile`, `.dockerignore`, `.npmrc`, `next.config.ts`, `tsconfig.json`, `postcss.config.mjs`, `eslint.config.mjs`, `proxy.ts`, `amvera.yml`. Paths use `/`, are sorted by JS code-unit order, and each entry is exactly `{path,sha256}` with SHA-256 of raw file bytes. The overall SHA-256 hashes UTF-8 `JSON.stringify(entries)` without whitespace. The lockfile hash is also recorded independently. Symlinks/special files in this scope are rejected. The algorithm is exported as `fingerprintInputs(root)` in `scripts/release/build-provenance.mjs` for offline reproduction against an exact GitHub checkout.

Excluded: documentation/README, `.github`, Git internals, generated `.next`/`.prescore-build`, dependencies, environment/credentials, file modes/mtime, and root files not listed above. Therefore equality proves only this defined source/config/test/lock **byte set**, not equality of the whole Git tree, dependencies installed by npm, environment, base image, final image, live data, or browser acceptance. Changing only excluded documentation does not alter the source fingerprint. Expanding the scope requires a new scope version.

When Git is available locally, HEAD/HEAD tree are retained only if every selected source byte matches its tracked Git blob and the checkout is clean, including untracked files. They are labelled `MATCHED_LOCAL_CHECKOUT`, not “GitHub commit”: an Amvera merge revision and a GitHub commit are distinct. A dirty checkout publishes no commit/tree. Docker continues to exclude `.git`; absent Git remains UNAVAILABLE while the byte fingerprint is still available. No remote branch lookup or expected SHA environment assignment is used.

The manifest is build evidence under the existing trusted build process, not a signed attestation. Its self-consistency checks do not protect against a compromised builder or someone replacing the artifact file. `buildId`, preparation/packaging timestamps and source fingerprint do not prove the container image digest. `publishedImageDigest` and `runningImageDigest` remain null in health; record publication logs and independently observed running-image metadata separately in the acceptance ledger.
